# Hi, I'm Lee 👋

I'm a full-stack software engineer working mainly with **C#/.NET, React and TypeScript**.

I enjoy building software around real business problems — applications where the interesting part isn't just getting a page or endpoint working, but understanding the domain, data, workflows and edge cases behind it.

I like working across the full stack and building larger projects that can evolve over time. I care about writing software that stays understandable and maintainable as it grows, rather than just getting something working and moving on.

## About me

- 💻 I enjoy working across backend APIs, frontend applications and relational databases
- 🧩 I'm particularly interested in business logic, domain modelling and how different parts of a system fit together
- 🛠️ I care a lot about code structure, naming, maintainability and keeping responsibilities clear
- 🧪 I prefer building incrementally, testing meaningful behaviour and validating each feature properly
- 🔍 I enjoy debugging and understanding the actual cause of a problem rather than patching around symptoms
- 📚 I'm always looking to improve how I design and structure software, not just add more frameworks to the list

## How I like to build software

I don't think good engineering means making everything complicated. I prefer starting with the simplest design that properly solves the problem, then allowing the architecture to grow when the requirements actually justify it.

In practice, I try to:

- keep responsibilities and boundaries clear
- model important business rules explicitly
- avoid duplication without creating abstractions too early
- treat testing as part of implementation rather than something added afterwards
- protect data integrity at both application and database level
- keep security in mind from the beginning
- favour readable, predictable code over clever code
- make changes small enough to understand, review and validate properly

I'm particularly interested in the point where **software design meets real business behaviour** — understanding not only how something should be implemented, but what the system should actually guarantee.

I'd rather build a few substantial projects properly and keep improving them over time than fill my GitHub with lots of small tutorial repositories.
